# ICE LOGIX Frontend — правила

Общие правила проекта — в корневом `AGENTS.md`. Здесь только то, что касается Mini App.

## Структура

- Рабочий код живёт в `public/` (vanilla JS). Next.js — только оболочка, раздающая `public/`.
- `public/app.html` и `index.html` — один и тот же каркас. Любая правка в них делается в обоих файлах одинаково.
- Не создавай копии `.js` в корне проекта. Источник правды — `public/`.
- Новый экран или функция — отдельный файл `public/js/modules/<имя>.js`. Ядро и роутер — `public/js/core/`, стили — `public/css/`. Не смешивай код разных экранов в одном файле.
- В конце нового модуля регистрируй функции на `window`:
  ```js
  if (typeof renderMyFeature === 'function') window.renderMyFeature = renderMyFeature;
  ```
- Подключай скрипт в `<head>` обоих HTML-файлов с версией: `<script src="/js/modules/x.js?v=20261028_01"></script>`.
- В инлайновые `<script>` HTML-файлов новую бизнес-логику не добавляй.

## Дизайн новых экранов

Новый экран, окно или компонент делай по скиллу `ice-design-system` (корень проекта: `.agents/skills/ice-design-system/SKILL.md`). Используй готовые классы `rd-*` из `public/css/ice-redesign.css` и переменные `--rd-*`. Нельзя: цветные классы Tailwind (`cyan`, `purple`, `pink`…), градиенты и неон, эмодзи вместо иконок, новые hex-цвета, текст «BYN», выдуманные цены и рейтинги. Проверка: `python scripts/check-design.py`.

Файл `public/css/ice-redesign-compat.css` генерируется скриптом `scripts/gen-redesign-compat.py` (переводит старые цвета Tailwind в синюю палитру), руками его не правь.

## Каркас приложения

- Все разделы рендерятся как обычный экран внутри `#content`. Полноэкранные оверлеи (`position: fixed; inset: 0`) для полноценных разделов запрещены, допустимы только для коротких диалогов (ввод карты, скан QR).
- Шапка `.app-header` и нижнее меню `#tabBar` / `.bottom-bar` видны всегда.
- В каждом подразделе есть кнопка «Назад» (`window.goBackGlobal()`).
- Подвала сайта под каталогами нет. Справка и контакты — в Профиле («О сервисе и помощь»).

## Кэш Telegram

Telegram сильно кэширует файлы. После правки любого файла в `public/js/`, `public/css/` или корневых скриптов подними параметр `?v=...` у этого файла в `public/app.html` и `index.html`.

## Проверка перед тем как сказать «готово»

1. `npm run build` без ошибок (Vercel собирает именно так).
2. Для интерфейса: запусти приложение локально и посмотри глазами, что вёрстка и основные сценарии (клик, форма, возврат назад) работают.
