## 🚨 КРИТИЧЕСКИЕ ПРАВИЛА АРХИТЕКТУРЫ (СТРОГО ОБЯЗАТЕЛЬНЫ ДЛЯ ИИ И РАЗРАБОТЧИКОВ):

### 1. ЗАПРЕТ НА РАЗДУВАНИЕ HTML-ФАЙЛОВ
* Файлы `index.html` и `public/app.html` — это исключительно чистый структурный каркас (не более ~250 строк).
* **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** писать логику, функции, бизнес-код или верстку экранов внутрь инлайн-тегов `<script>` в `index.html` / `public/app.html`.

### 2. ПРИНЦИП МОДУЛЬНОСТИ (ОДНА ФИЧА — ОДИН ФАЙЛ)
* Любая новая функциональность, раздел или экран **ОБЯЗАНЫ** создаваться в отдельном файле:
  * Новые пользовательские или админ-экраны $\rightarrow$ `public/js/modules/<имя-фичи>.js`
  * Системное ядро и роутер $\rightarrow$ `public/js/core/`
  * Словари, иконки, справочники $\rightarrow$ `public/js/`
  * Стили дизайн-системы $\rightarrow$ `public/css/`
* Запрещено смешивать код разных экранов (например, заказы с калькулятором или отзывы с админкой).

### 3. ПОДКЛЮЧЕНИЕ И ЭКСПОРТ В WINDOW
* При создании нового модуля в конце файла обязательно регистрировать функции в глобальном объекте:
  ```javascript
  if (typeof renderMyFeature === 'function') window.renderMyFeature = renderMyFeature;
  if (typeof attachMyFeatureHandlers === 'function') window.attachMyFeatureHandlers = attachMyFeatureHandlers;
  ```
* Подключать скрипт в `<head>` в `public/app.html` и `index.html` с версионированием (`?v=...`):
  ```html
  <script src="/js/modules/my-feature.js?v=20261005"></script>
  ```

### 4. ЕДИНСТВЕННЫЙ ИСТОЧНИК ПРАВДЫ
* Все исходники живут в `public/`.
* При любых правках разметки `public/app.html` и `index.html` обновляются синхронно байт-в-байт.
* Запрещено создавать дублирующие `.js` файлы в корне проекта.

### 5. ОБЯЗАТЕЛЬНЫЙ КОНТРОЛЬ КАЧЕСТВА ПЕРЕД ОТВЕТОМ
* После любых изменений в JS/CSS **всегда** выполнять:
  1. Синтаксическую проверку (`node -c`).
  2. Продакшен-билд (`npm run build`) — убеждаться, что компиляция проходит с 0 ошибок.
  3. Фиксацию изменений в Git (`git add`, `git commit`, `git push origin main`).
